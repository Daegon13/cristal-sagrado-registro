# Neon y Vercel: instalación de Registro

Estado: la aplicación falla de forma cerrada hasta que se configuren los servicios. No usar datos personales reales para la prueba.

1. Crear un proyecto Neon **nuevo y exclusivo** para `cristal-sagrado-registro`, en plan Free y región AWS São Paulo si está disponible. No conectar bases de otros proyectos. Crear una rama de ensayo separada para `feat/neon-migration` y confirmar qué rama corresponde a cada despliegue Preview.
2. Habilitar **Managed Better Auth** en la rama de ensayo. Tomar `NEON_AUTH_BASE_URL` de esa rama y generar `NEON_AUTH_COOKIE_SECRET` de 32 o más caracteres aleatorios. Configurar dominios de confianza de los previews y verificación de correo en Neon. El proxy de la app rechaza `POST /api/auth/sign-up/*`; crear las dos cuentas autorizadas administrativamente, sin compartir contraseñas. Verificar si la configuración de Neon permite cerrar el alta directa en su endpoint; la guía de producción vigente advierte que el registro puede seguir abierto. Aunque alguien se registre directamente, sin `membership` no podrá acceder a datos.
3. Aplicar `sql/003_neon_initial.sql` en la **rama vacía de ensayo**. No aplicar `sql/001_initial.sql` ni `sql/002_hardening.sql`: pertenecen al MVP Supabase y contienen SQL incompatible. La migración 003 usa `text` para `user_id`, porque Better Auth no garantiza UUID. Verificar tablas, claves, disparadores y que `neon_auth` exista después de habilitar Auth.
4. Obtener los IDs **reales** de las dos cuentas desde Neon Auth. En SQL Editor de la rama de ensayo, ejecutar y revisar: `INSERT INTO organizations(name) VALUES ('Cristal Sagrado') RETURNING id;` y luego `INSERT INTO memberships(org_id,user_id,role) VALUES ('<ORG_ID>','<LUCIA_ID>','admin'),('<ORG_ID>','<DIEGO_ID>','admin');`. No crear usuarios ficticios ni otorgar membresía por email aportado por el navegador.
5. Conectar Neon al proyecto Vercel `cristal-sagrado-registro` únicamente. Configurar `DATABASE_URL` de la rama de ensayo en Preview, y `NEON_AUTH_BASE_URL` de esa **misma rama**. Configurar `NEON_AUTH_COOKIE_SECRET` en Preview como secreto. No copiar valores de Production a Preview. La integración de Vercel puede provisionar algunas variables: comprobar sus nombres efectivos antes de crear duplicados. Nunca usar `NEXT_PUBLIC_` para secretos.
6. Configurar `REPORT_ORG_ID` con el UUID real, `CRON_SECRET` aleatorio, `REPORT_TO_EMAIL` fijo, `REPORT_FROM_EMAIL` de dominio verificado y `RESEND_API_KEY` solo cuando se vaya a probar envío autorizado. En pruebas automáticas no configurar una clave Resend real; usar un doble de prueba. El cron corre los lunes 12:00 UTC, equivalentes a 09:00 en Montevideo.
7. Ejecutar `npm ci`, `npm run typecheck`, `npm test`, `npm run build`. Desplegar Preview, confirmar su build READY y probar sesión de ambas cuentas, usuario sin membresía, consulta, venta, cobro parcial, devolución, anulación, exportación e informe contra la rama de ensayo, con datos ficticios. Inspeccionar el correo recibido sin PII. Un build o una URL de Preview sin conexión no demuestra funcionalidad.
8. Antes de Production, exportar respaldo JSON desde la app y realizar una restauración de ensayo en otra rama; comparar conteos y totales. Usar la función de restauración a un punto en el tiempo de Neon como respaldo de infraestructura. Aplicar migración a Production solamente tras revisión y respaldo. No fusionar `main` automáticamente.

## Recuperación

Ante error de esquema, detener escrituras y envíos, registrar el punto de recuperación, crear una rama de restauración de Neon y comparar con el JSON exportado. No ejecutar `DROP TABLE` en la rama con datos. La migración 003 es para instalación nueva; su reversión por SQL destruiría datos, por lo que se usa restauración de rama o copia de seguridad verificada.

Los informes reservan una fila `pending` antes del envío y usan una clave de idempotencia de Resend. Si hay un error ambiguo de red, la fila queda pendiente y la app evita reenviar; verificar en Resend antes de resolver manualmente. Los informes de prueba no deben enviarse al Gmail real.
